# keenetic/

Скрипты и заготовки команд для роутеров Keenetic (KeeneticOS 3.x/4.x).

| Файл | Назначение |
|---|---|
| `meta-routes.sh` | Статические маршруты на сети Meta (Instagram, Facebook, WhatsApp) через выбранный интерфейс (VPN/прокси/второй провайдер). Умеет добавлять и снимать маршруты через `ndmc` прямо на роутере (нужен Entware) либо печатать готовые команды для вставки в веб-CLI. |
| `meta-routes-add.txt` | Готовый список команд `ip route ... Wireguard0 auto` — вставить в командную строку роутера. Сгенерирован скриптом (`sh meta-routes.sh cli Wireguard0`). |
| `meta-routes-del.txt` | То же для снятия маршрутов (`no ip route ...`). |

## Быстрый старт (без Entware)

1. Поднимите VPN-подключение (WireGuard/OpenVPN/…) и **снимите** галку
   «Использовать для выхода в Интернет» — иначе весь трафик уйдёт в туннель.
2. Узнайте системное имя интерфейса: веб-интерфейс → *Управление* →
   *Диагностика* → *Командная строка*, выполните `show interface`
   (обычно `Wireguard0`, `OpenVPN0`, `L2TP0`, `Proxy0`).
3. Если имя отличается от `Wireguard0` — замените его в `meta-routes-add.txt`
   (`sed -i 's/Wireguard0/OpenVPN0/' meta-routes-add.txt`) или сгенерируйте
   файл заново: `sh meta-routes.sh cli OpenVPN0`.
4. Вставьте содержимое файла в командную строку роутера. Последняя строка
   `system configuration save` сохраняет конфигурацию.
5. Проверка: `show ip route` — маршруты должны быть на нужном интерфейсе.

Ключ `auto` в конце команды означает, что маршрут переустанавливается
автоматически при поднятии интерфейса, поэтому после перезагрузки роутера
ничего повторять не нужно.

Откат — содержимое `meta-routes-del.txt` тем же способом.

## Запуск на роутере (с Entware)

```sh
mkdir -p /opt/scripts
# скопировать meta-routes.sh в /opt/scripts (scp, wget, vi)
sh /opt/scripts/meta-routes.sh add Wireguard0     # добавить
sh /opt/scripts/meta-routes.sh show Wireguard0    # проверить
sh /opt/scripts/meta-routes.sh del Wireguard0     # откатить
```

Команды выполняются через `ndmc`, конфигурация сохраняется автоматически.

## Состав списка

В исходном списке было 52 записи; узлы, уже попадающие в свои подсети
(все `157.240.x.x` → `157.240.0.0/16`, `57.144.110.1` и `57.144.112.34` →
`57.144.96.0/19`, `31.13.72.0/24` → `31.13.0.0/16`), схлопнуты — осталось
**34 префикса**. Полный список с комментариями: `sh meta-routes.sh list`.

Список поделён на две группы:

- **core** (25 префиксов) — диапазоны, анонсируемые Meta (AS32934/AS63293);
- **extra** (9 префиксов) — сети из исходного списка, которые Meta
  не принадлежат либо шире её реальных выделений:
  `142.250.0.0/15` и `173.194.10.0/24` — Google,
  `99.84.0.0/16` — AWS CloudFront, `147.75.0.0/16` — Equinix Metal,
  `213.102.128.0/24` — Telia, плюс `45.130.4.0/24`, `77.240.43.0/24`,
  `87.245.208.0/24`, `87.245.223.97`. Заворачивать их в туннель
  не обязательно, а для Google-сетей — вредно (уедут и другие сервисы).

Только «чистые» сети Meta:

```sh
META_SCOPE=core sh meta-routes.sh cli Wireguard0   # печать команд
META_SCOPE=core sh meta-routes.sh add Wireguard0   # применить на роутере
```

Готовые `.txt` собраны по полному списку (`META_SCOPE=all`).

## Ограничения

- Маршруты статические: если Meta начнёт отдавать адреса из новых сетей,
  список придётся обновить (`meta-routes.sh list` → правка секции `nets()`).
- DNS не заворачивается: при DNS-блокировках дополнительно настройте
  DNS-over-TLS/HTTPS в *Интернет-фильтры* → *DNS-серверы*.
