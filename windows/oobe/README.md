# windows/oobe/

Автоматическая установка и настройка рабочей станции Windows 10/11: от файла
ответов до установленного ПО и правок реестра — без вопросов на экране.

Документация Microsoft по файлам ответов:
<https://learn.microsoft.com/ru-ru/windows-hardware/customize/desktop/unattend/>
Идея запуска OOBE одной командой: <https://www.outsidethebox.ms/22491/>

## Файлы

| Файл | Назначение |
|---|---|
| `AutoUnattend.xml` | Файл ответов для **чистой установки** с нуля (проходы `windowsPE` + `oobeSystem`): локали, обход требований Win11, локальный администратор `Admin`. |
| `UnattendOOBE.xml` | Файл ответов **только для прохода `oobeSystem`** — для повторного прогона OOBE на уже установленной системе через `sysprep /oobe`. |
| `oobe.ps1` | Скачивает `UnattendOOBE.xml`, проверяет его, раскладывает пост-установочные файлы и запускает `sysprep /oobe /reboot /unattend:…`. |
| `postinstall.ps1` | Пост-установка при первом входе: ПО, правки реестра, системные настройки. Логику не правят — правят `postinstall.json`. |
| `postinstall.json` | **Единственный файл, который нужно настроить под себя**: адрес NAS, список ПО, правки реестра, системные параметры. |
| `office/configuration-ProPlus2024Volume.xml` | Эталонная конфигурация ODT: Office LTSC профессиональный плюс 2024, набор по умолчанию. |
| `office/configuration-ProPlus2021Volume.xml` | То же для Office LTSC Professional Plus 2021. |
| `office/configuration-M365Apps.xml` | Конфигурация ODT для Microsoft 365 Apps (подписка). |

## Сценарий 1: повторный прогон OOBE на уже установленной Windows

Применяется, когда система уже стоит (предустановленная ОС от вендора, образ
Hyper-V, машина после возврата от пользователя). Драйверы, активация и SID
сохраняются — `sysprep` запускается **без** `/generalize`.

На первом экране OOBE (выбор региона) нажмите <kbd>Shift</kbd>+<kbd>F10</kbd> и выполните:

```powershell
irm https://raw.githubusercontent.com/gpas45/scripts/main/windows/oobe/oobe.ps1 -OutFile $env:TEMP\oobe.ps1
powershell -ExecutionPolicy Bypass -File $env:TEMP\oobe.ps1
```

Скрипт по очереди спросит всё, что нужно, — человек присутствует только на
этом шаге, дальше всё идёт само:

```
Откуда брать дистрибутивы:
  1 — HTTPS, из интернета через обратный прокси
  2 — SMB, внутри локальной сети напрямую с NAS
  Подключение [1]:
  Адрес раздачи [https://oobe.dioservice.ru/Deploy]:
  Учётная запись [deploy]:
  Пароль: ********
  Проверяю доступ…
  Доступ есть: HTTP 200, https://oobe.dioservice.ru/Deploy/7-Zip/7z-x64.msi

  Ставить Microsoft Office, режим odt? [y/N]:

================ План установки ================
  Источник ПО      : https://oobe.dioservice.ru/Deploy (HTTP)
  Учётная запись   : deploy
  Программы        : 10
      - 7-Zip
      - WinRAR
      - Notepad++
      - Adobe Acrobat Reader (64-bit)
      - Google Chrome
      - Яндекс Браузер для организаций
      - КриптоПро CSP
      - КриптоПро ЭЦП Browser plug-in
      - Сертификаты УЦ СКБ Контур
      - Aspia Host
  Дополнительно    : VLC, Far Manager
  Сертификаты      : Russian Trusted Root CA, Russian Trusted Sub CA, Russian Trusted Sub CA 2024
  Правки реестра   : 43
  Office           : не ставим
  Часовой пояс     : Ekaterinburg Standard Time
  Администратор    : Admin (пароль из файла ответов — смените после установки)
===============================================
  Enter — начать, n — изменить набор программ, q — отмена:
```

После правки набора план показывается заново — видно, что получилось, и можно
переделать ещё раз. Выход из цикла только по Enter или `q`.

Если доступа к раздаче нет, скрипт покажет причину и предложит ввести всё
заново — адрес и пароль правятся на месте, не доходя до перезагрузки.

Пароль вводится скрыто и сохраняется в `C:\ProgramData\oobe\nas.cred` с правами
только для SYSTEM и администраторов. Ответы складываются в
`C:\ProgramData\oobe\postinstall.override.json`, который `postinstall.ps1`
подхватит при первом входе; сам `postinstall.json` править не нужно.

Чтобы ничего не спрашивалось, задайте всё ключами:

```powershell
powershell -ExecutionPolicy Bypass -File $env:TEMP\oobe.ps1 -NoPrompt `
    -NasBaseUrl https://oobe.dioservice.ru/Deploy -NasUser deploy -NasPassword 'пароль'
```

### Проверка доступа к раздаче

Выполняется до запуска sysprep и повторяется после каждой смены адреса, учётной
записи, пароля или режима HTTPS/SMB. Скрипт запрашивает первый дистрибутив из
списка — так сразу видно и доступность, и аутентификацию, и правильность
раскладки файлов.

| Строка | Что значит |
|---|---|
| `ОК — HTTP 200, …` | Источник отвечает, аутентификация пройдена, файл на месте |
| `с оговоркой — … 404 …` | Доступ и аутентификация в порядке, но файла по этому пути нет — проверьте раскладку |
| `НЕТ — 401 …` | Аутентификация не пройдена: неверная учётная запись или пароль |
| `НЕТ — 403 …` | Доступ запрещён (ограничение по адресам, права на папке) |
| `НЕТ — … недоступен …` | Хост не отвечает: адрес, DNS, сеть, сертификат |

Если доступа нет, пункт «продолжить» потребует явного подтверждения: после
перезагрузки дистрибутивы брать будет неоткуда, встанут только winget-пакеты,
правки реестра и системные настройки.

Ту же проверку делает `postinstall.ps1` при первом входе. Не прошла — источник
отключается, запись уходит в сводку и лог, а пакеты сразу идут за winget и
прямыми ссылками, вместо того чтобы отваливаться по таймауту поодиночке.

Пункт 3 открывает нумерованный список всех пакетов: номера через запятую
(`1,3,5`), диапазоны (`1-4`), `all`, `none`; Enter оставляет набор по умолчанию.
Пункт 4 спрашивает учётную запись и пароль к раздаче — пароль вводится скрыто
и сохраняется в `C:\ProgramData\oobe\nas.cred` с правами только для SYSTEM и
администраторов.

Ответы складываются в `C:\ProgramData\oobe\postinstall.override.json`, который
`postinstall.ps1` подхватит при первом входе. Сам `postinstall.json` править не
нужно.

Чтобы ничего не спрашивалось, задайте всё ключами:

```powershell
powershell -ExecutionPolicy Bypass -File $env:TEMP\oobe.ps1 -NoPrompt `
    -NasBaseUrl https://oobe.dioservice.ru/Deploy -NasUser deploy -NasPassword 'пароль'
```

Короткий вариант «в одну команду» из статьи-источника тоже работает, но
скрипты здесь сохранены в UTF-8 **с BOM** (иначе Windows PowerShell 5.1
портит кириллицу), а `iex` на строке с ведущим BOM падает — его надо срезать:

```powershell
powershell -c "iex ((irm https://raw.githubusercontent.com/gpas45/scripts/main/windows/oobe/oobe.ps1) -replace '^\uFEFF')"
```

Дальше всё само: перезагрузка, OOBE без вопросов, автовход под `Admin`,
пост-установка, итоговый лог в `C:\ProgramData\oobe\postinstall.log`.

> ⚠️ Запуск скрипта из интернета небезопасен: содержимое по ссылке может быть
> подменено, а выполняется оно с правами SYSTEM. Для серийного развёртывания
> указывайте ссылку на конкретный коммит и сверяйте хеш:
> `oobe.ps1 -AnswerFileUri '…/<sha>/windows/oobe/UnattendOOBE.xml' -Sha256 '<хеш>'`.

## Сценарий 2: чистая установка с флешки

1. Положите `AutoUnattend.xml` в корень установочной флешки под именем
   `autounattend.xml`.
2. Скопируйте туда же папку `oobe` с `postinstall.ps1` и `postinstall.json`
   (и, при необходимости, `nas.cred`) — `FirstLogonCommands` ищет
   `<диск>:\oobe\postinstall.ps1` на всех томах, а если не находит, берёт
   скрипт из репозитория.
3. Загрузитесь с флешки.

## Дистрибутивы на Synology NAS

`postinstall.ps1` берёт установщики в порядке **NAS → winget → прямая ссылка**
(поле `source` у каждого пакета: `auto`, `nas`, `winget`, `url`).

У Яндекс Браузера, КриптоПро CSP и плагина, сертификатов Контура и Aspia Host
стоит `source: "nas"` — другого источника у них не бывает. Если файла на месте
нет, такой пакет не подменяется ничем, а сообщает, какого именно файла не
хватает, вместо туманного «не задан ни один источник».

### Старый winget в образе

Набор ключей winget отличается от версии к версии, поэтому скрипт определяет её
через `winget --version` и подставляет флаги по ней. Конкретно
`--disable-interactivity` появился примерно в 1.4: в 1.2 (Windows Server 2022,
LTSC, образы без обновлённого App Installer) его нет, и winget падает на разборе
аргументов, не дойдя до установки. На таких версиях флаг не добавляется —
тихого режима `--silent` достаточно.

Если winget в образе старый, лучше обновить App Installer один раз, до sysprep,
и дальше не думать об этом. Из Store на Server-редакциях он не ставится,
поэтому `msixbundle` берётся из релизов
[microsoft/winget-cli](https://github.com/microsoft/winget-cli/releases):

```powershell
Add-AppxProvisionedPackage -Online `
  -PackagePath .\Microsoft.DesktopAppInstaller_8wekyb3d8bbwe.msixbundle `
  -SkipLicense
```

Ожидаемая раскладка раздачи (пути задаются в `software[].nasPath`):

### Вариант по умолчанию: HTTPS (`"type": "http"`)

Установка идёт за пределами локальной сети, поэтому по умолчанию дистрибутивы
забираются по HTTPS с `https://oobe.dioservice.ru/Deploy`.

Имя у HTTPS-раздачи отдельное, и это намеренно: `nas.dioservice.ru` остаётся за
интерфейсом DSM и SMB (внутри сети оно резолвится прямо в NAS), а
`oobe.dioservice.ru` ведёт на обратный прокси, который отдаёт WebDAV.

Схема доступа:

```
клиент --HTTPS--> oobe.dioservice.ru (Traefik) --HTTPS 5006--> nas.dioservice.ru (WebDAV)
```

На Synology:

1. **Центр пакетов** → установите **WebDAV Server**, включите в нём HTTPS
   (порт 5006). Общая папка `Deploy` отдаётся по адресу `/Deploy/...` — имя
   папки и есть первый сегмент пути, поэтому никаких переписываний пути
   в Traefik не нужно. Регистр имеет значение: Apache, на котором работает
   WebDAV Server, сравнивает путь посимвольно, и `PathPrefix` в Traefik тоже.
   Папка `Deploy` по адресу `/deploy` даст 404.
2. **Панель управления → Пользователь и группа** → учётная запись `deploy`:
   на вкладке **Разрешения** папка `Deploy` только на чтение, остальные — нет
   доступа; на вкладке **Приложения** разрешены только WebDAV и, если
   разворачиваете ещё и изнутри сети, SMB. Вход в DSM запретите, 2FA не
   включайте — с ней WebDAV не работает.
3. **Панель управления → Безопасность → Брандмауэр** — порт 5006 открыть
   только адресу Traefik.
4. **Панель управления → Безопасность → Доверенные прокси** — добавьте адрес
   Traefik, иначе автоблокировка DSM при переборе пароля заблокирует сам
   Traefik и отвалятся все внешние установки сразу.

Обратный прокси DSM для этого не нужен и не получится: он маршрутизирует
только по паре имя+порт, без путей, а `nas.dioservice.ru:443` уже занято
интерфейсом DSM.

Пример конфигурации Traefik (file provider; NAS не контейнер, метки Docker
здесь не применимы):

```yaml
http:
  routers:
    oobe-deploy:
      rule: "Host(`oobe.dioservice.ru`) && PathPrefix(`/Deploy`)"
      entryPoints:
        - websecure
      service: nas-webdav
      tls:
        certResolver: letsencrypt

  services:
    nas-webdav:
      loadBalancer:
        passHostHeader: true
        serversTransport: nas-tls
        servers:
          - url: "https://nas.dioservice.ru:5006"

  serversTransports:
    nas-tls:
      serverName: "nas.dioservice.ru"
      insecureSkipVerify: true   # убрать, когда на DSM будет валидный сертификат
```

`nas.dioservice.ru` в адресе backend безопасно только потому, что внутри сети
это имя резолвится прямо в NAS. Имя самой раздачи (`oobe.dioservice.ru`) так
писать нельзя — Traefik получит собственный адрес и запрос уйдёт в петлю.

Раздача закрывается базовой аутентификацией: заполните `nas.user` и передайте
пароль через `-NasPassword` либо файл `nas.cred`. Скрипт отправляет заголовок
`Authorization` сразу, не дожидаясь ответа 401. Проверять аутентификацию должен
DSM — Traefik пробрасывает заголовок `Authorization` дальше сам.

> ⚠️ Раздача доступна из интернета, а дистрибутивы КриптоПро, Контура и Яндекс
> Браузера распространяются по лицензии. Закройте её базовой аутентификацией
> или ограничением по адресам — открытая раздача это и утечка лицензионного ПО,
> и готовый канал подмены установщиков.

### Альтернатива: SMB (`"type": "smb"`)

Для развёртывания внутри сети или через VPN. Поменяйте `nas.type` на `smb` —
путь берётся из `nas.share`.

На NAS: **Панель управления → Общая папка** → папка `Deploy`, и
**Пользователь и группа** → учётная запись `deploy` с правом **только на чтение**.
Пароль передаётся так же, как для HTTPS.

> Гостевой доступ не подойдёт: Windows 10/11 по умолчанию запрещает
> небезопасный гостевой вход в SMB. Включать `AllowInsecureGuestAuth` не стоит —
> это открывает машину для атак на подмену SMB-сервера. Наружу SMB не публикуют.

### Смена адреса раздачи

Править `postinstall.json` для этого не нужно. Приоритет такой:

```
postinstall.json  ->  postinstall.override.json  ->  ключи командной строки
```

| Как | Когда |
|---|---|
| Экран плана в `oobe.ps1`, пункты 2/4/5 | Обычный прогон в OOBE: отвечаете один раз, первый вход подхватывает сам |
| `oobe.ps1 -NasBaseUrl … -NasType … -NasShare … -NasUser … -NoPrompt` | Без вопросов, для автоматизации |
| `postinstall.ps1 -NasBaseUrl …` | Ручной повторный запуск на уже настроенной машине |

`postinstall.override.json` лежит в `C:\ProgramData\oobe\` рядом с конфигом и
содержит только изменённое — адрес, учётную запись и выбранный набор ПО:

```json
{
  "nas": { "baseUrl": "https://backup.dioservice.ru/Deploy", "user": "deploy" },
  "include": ["7-Zip", "Notepad++", "Google Chrome"]
}
```

## Настройка `postinstall.json`

Профили: у каждого пакета и каждой правки реестра есть `profiles`. Применяется
только то, чей профиль передан в `-Profiles` (элемент без `profiles` — всегда).

```powershell
# базовый набор
powershell -ExecutionPolicy Bypass -File .\postinstall.ps1
# базовый + браузеры + прочее
powershell -ExecutionPolicy Bypass -File .\postinstall.ps1 -Profiles base,browser,extra
```

| Профиль | Что входит |
|---|---|
| `base` | **Набор по умолчанию:** 7-Zip, WinRAR, Notepad++, Adobe Reader, Chrome, Яндекс Браузер, КриптоПро CSP, КриптоПро ЭЦП plug-in, сертификаты УЦ СКБ Контур, Aspia Host + сертификаты Минцифры, все правки реестра, системные настройки |
| `extra` | **Дополнительные пакеты:** VLC, Far Manager — по умолчанию не ставятся |
| `browser` | Chrome, Яндекс Браузер — для точечного прогона |
| `crypto` | КриптоПро CSP, КриптоПро ЭЦП plug-in, сертификаты УЦ СКБ Контур — для точечного прогона |
| `remote` | Aspia Host — для точечного прогона |

Пакеты набора по умолчанию входят и в `base`, и в свою категорию: `-Profiles base`
ставит всё перечисленное, `-Profiles crypto` — только криптографию.

### Выбор того, что ставить

Профили — не единственный способ. Есть три ключа, они складываются:

```powershell
# спросить интерактивно: нумерованный список, звёздочкой отмечено выбранное профилями
.\postinstall.ps1 -Select

# только определённые пакеты, профили при этом игнорируются
.\postinstall.ps1 -Include 'Крипто*','Контур','Aspia'

# набор профилей минус лишнее
.\postinstall.ps1 -Profiles base,browser -Exclude Chrome
```

`-Include` и `-Exclude` сравниваются с полем `name` без учёта регистра, по
подстроке и по шаблонам (`*`, `?`). В интерактивном режиме принимаются номера
через запятую (`1,3,5`), диапазоны (`1-4`), `all`, `none`; пустой ввод оставляет
набор по профилям.

При ручном запуске `postinstall.ps1` печатает план и спрашивает подтверждение
(Enter — продолжить, `n` — изменить набор, `q` — выход).

> В `FirstLogonCommands` обязателен `-NoPrompt`, он там и стоит. Сеанс первого
> входа интерактивный, поэтому без этого ключа установка остановилась бы на
> вопросе, и человек увидел бы пустой рабочий стол. `-Select` там тоже
> задавать нельзя.

#### Пакеты, которых нет в winget

Их дистрибутивы кладутся на NAS, `wingetId` у них пустой.

| Пакет | Где взять | Замечания |
|---|---|---|
| Яндекс Браузер для организаций | [личный кабинет корпоративного браузера](https://browser.yandex.ru/corp) | Ключи тихой установки у разных сборок отличаются |
| КриптоПро CSP | cryptopro.ru по вашей лицензии | Проверяется по контрольным суммам (см. ниже). Лицензия вводится отдельно: `cpconfig.exe -license -set <серийный номер>` |
| КриптоПро ЭЦП Browser plug-in | там же | Только `cadesplugin.exe`, MSI у плагина нет. Это бутстраппер, ключи с одним дефисом: `-silent -norestart -noyandex -noroot`. Полный список — `cadesplugin.exe -?` |
| WinRAR | rarlab.com по вашей лицензии | Есть и в winget (`RARLab.WinRAR`), но тогда это будет пробная версия. Положите `rarreg.key` рядом с дистрибутивом на NAS |
| Сертификаты УЦ СКБ Контур | личный кабинет Контура | `SKBKontur.InstallCertificates`, консольная утилита, сертификаты зашиты внутрь, требует прав администратора. Заканчивает работу через `pause` — закрывается общим правилом про stdin (см. ниже) |
| Aspia Host | [github.com/dchapyshev/aspia/releases](https://github.com/dchapyshev/aspia/releases) | После установки хост нужно настроить (пароль/ID), иначе подключиться не получится |

#### КриптоПро ЭЦП Browser plug-in

У бутстраппера `cadesplugin.exe` два ключа важны не только ради тишины:

- **`-noyandex`** — без него бутстраппер ставит обычный Яндекс Браузер, хотя
  рядом у нас уже ставится корпоративная сборка;
- **`-noroot`** — без него он добавляет корневые сертификаты из своего архива
  мимо секции `certificates`, где доверие задаётся явно и с проверкой
  отпечатков. Если эти сертификаты всё-таки нужны, замените на `-root`.

#### Контрольные суммы дистрибутивов

У пакета может быть блок `checksums` — файл проверяется **до** запуска
установщика, несовпадение прерывает установку этого пакета:

```json
"checksums": {
  "md5": "326921d3551f371fcb2dccb7f183fcc4",
  "sha256": "",
  "gost2012_256": "C148910DDD1143E10F4BE68AD048F5738CB359DABE2C28735486F5546E6B41BC"
}
```

| Алгоритм | Когда проверяется |
|---|---|
| `sha256`, `sha1`, `md5` | Всегда, средствами `Get-FileHash` |
| `gost2012_256` | Только если на машине уже есть `cpverify.exe` |

ГОСТ Р 34.11-2012 Windows считать не умеет: его вычисляет `cpverify` из состава
КриптоПро CSP. На чистой машине его ещё нет, поэтому **сам CSP проверяется по
MD5**, а ГОСТ подтвердится при повторном прогоне. Если знаете SHA256 своего
дистрибутива — впишите: он проверяется всегда и надёжнее MD5, у которого
коллизии подбираются.

Поведение строгое: если задана хотя бы одна сумма, но проверить не удалось ни
одной, пакет не ставится. Пустой блок или его отсутствие означают, что проверять
нечего.

#### Настройка после установки

Установщики не подхватывают конфиги, лежащие рядом с ними. Поэтому у пакета
есть два механизма — положить файл и выполнить команду.

**`configFiles`** копирует файл туда, где его читает программа:

```json
"configFiles": [
  { "nasPath": "MyApp/settings.ini", "destination": "%ProgramData%\\MyApp\\settings.ini" }
],
"restartService": "MyAppService"
```

Файл берётся с того же источника, что и дистрибутив, каталог назначения
создаётся, переменные вида `%ProgramData%` раскрываются. Если указано имя
службы, она перезапускается, чтобы перечитать настройки.

**`postInstall`** выполняет команду, когда программа умеет импортировать
настройки сама. Так сделано у Aspia Host:

```json
"postInstall": {
  "nasPath": "Aspia/aspia-host-config.json",
  "executable": "%ProgramFiles%\\Aspia\\Host\\aspia_host.exe",
  "arguments": "--import \"{file}\" --silent",
  "timeoutSeconds": 180
}
```

`{file}` заменяется на путь к скачанному файлу. Если `executable` по
указанному пути не найден, он ищется по имени в `Program Files` — каталог
установки у разных сборок отличается.

Ключи `--import` и `--silent` взяты из исходников Aspia
(`source/host/main.cc`): конфиг у хоста именно импортируется, копировать его
в каталог настроек бесполезно.

#### Установщики, которые ждут нажатия клавиши

Установщики часто заканчивают строкой «Для продолжения нажмите любую клавишу» —
это `pause`, и он читает stdin. При автоматическом прогоне нажимать некому: шаг
провисел бы до `timeoutSeconds` и попал в сводку как ошибка, хотя работа уже
сделана. На этом спотыкались и утилита Контура, и Яндекс Браузер.

Поэтому **всем установщикам по умолчанию подставляется пустой stdin**: `pause`
сразу получает конец файла и программа завершается сама. Тем, кто stdin не
читает, это ничем не мешает. Дочерние процессы наследуют тот же дескриптор,
так что работает и для `msiexec`, запускающего что-то своё.

Отключается у отдельного пакета через `"stdinNull": false` — если установщику
по какой-то причине нужен настоящий ввод.

У каждого пакета можно задать `timeoutSeconds`: если установщик не завершился
за это время (например, что-то спросил), процесс снимается, шаг помечается
ошибкой, а остальная настройка продолжается. По умолчанию 1800 с. Это важно
именно для автоматического прогона: зависший установщик иначе навсегда
подвесит первый вход в систему.

Яндекс Браузер для организаций в winget не публикуется — только MSI. Скачайте
его в [личном кабинете корпоративного браузера](https://browser.yandex.ru/corp),
при необходимости соберите с нужной конфигурацией и положите на NAS как
`YandexBrowser\Yandex.msi`. Ключи тихой установки у разных сборок отличаются —
проверьте на тестовой машине ([документация по развёртыванию](https://browser.yandex.ru/support/browser-corporate/ru/deployment/windows/deployment)).

Добавить свой пакет — одна запись в `software`:

```json
{
  "name": "Моя программа",
  "source": "auto",
  "wingetId": "",
  "nasPath": "MyApp\\setup.msi",
  "installerArgs": "/qn /norestart",
  "installerUrl": "",
  "profiles": ["base"]
}
```

`.msi` ставится через `msiexec /i … /qn /norestart`, `.ps1` — через
PowerShell, всё остальное запускается напрямую с `installerArgs`.
Коды возврата `3010`/`1641` трактуются как «нужна перезагрузка», а не как ошибка.

### Доверенные сертификаты

Секция `certificates` ставит сертификаты Минцифры, без которых не открываются
сайты госуслуг, Сбербанка и части госорганов. Их три:

| Сертификат | Хранилище | Отпечаток SHA1 | Действует до |
|---|---|---|---|
| Russian Trusted Root CA | `Root` | `8FF915CCAB7BC16F8C5C8099D53E0E115B3AEC2F` | 27.02.2032 |
| Russian Trusted Sub CA (2022) | `CA` | `335D43F53451B781535FF3882DF713D3C14F8A01` | 06.03.2027 |
| Russian Trusted Sub CA 2024 | `CA` | `6741AB02CF6598C09652DC34D2DC095904E32B52` | 19.07.2029 |

Выпускающих именно два: у сертификата 2024 года другой ключ, и то, что подписано
им, без него не проверяется. Ставить нужно оба.

Файлы лежат в [`certificates/`](certificates/) и продублированы на NAS. Порядок
источников обычный: сначала `nasPath`, при неудаче `url` на этот репозиторий.

| Поле | Назначение |
|---|---|
| `nasPath` | Файл на NAS — основной источник |
| `url` | Резервная прямая ссылка, если на NAS файла нет |
| `store` | `Root` — доверенные корневые ЦС, `CA` — промежуточные |
| `thumbprint` | Ожидаемый отпечаток SHA1; при несовпадении сертификат не ставится |

Отпечатки в конфиге уже заполнены и сняты с файлов, полученных с
<https://www.gosuslugi.ru/crt>; цепочка проверена — оба выпускающих подписаны
этим корнем. При несовпадении отпечатка сертификат не установится, и шаг
попадёт в сводку как ошибка. Если `thumbprint` оставить пустым, сертификат
установится, но в лог уйдёт предупреждение с фактическим отпечатком.

Проверка нужна не формально: установленный корневой ЦС позволяет выпускать
сертификаты, которым машина будет доверять для любого сайта, так что подменённый
файл — это не испорченная установка, а доверенный злоумышленник.

Узнать отпечаток файла:

```powershell
(Get-PfxCertificate .\Russian_Trusted_Root_CA.cer).Thumbprint
```

Сертификаты ставятся до установки ПО — иначе HTTPS внутренних серверов, откуда
идут дистрибутивы, может не открыться. Уже установленный сертификат
пропускается, так что повторный запуск безопасен.

### Правки реестра

Тоже данные:

```json
{
  "description": "Показывать расширения файлов",
  "path": "HKCU:\\Software\\Microsoft\\Windows\\CurrentVersion\\Explorer\\Advanced",
  "name": "HideFileExt",
  "type": "DWord",
  "value": 0,
  "profiles": ["base"]
}
```

Безымянное значение ключа (в regedit — «(По умолчанию)») задаётся через
`"name": "(default)"` либо пустым `name`. Так включается классическое
контекстное меню Windows 11: пустая строка в `InprocServer32` под CLSID
`{86CA1AA0-34AA-4E8B-A509-50C905BAE2A2}`. Эффект появляется после перезапуска
Проводника — за это отвечает `system.restartExplorer`.

Политики Windows Update занимают два разных раздела, и перепутать их легко:

| Раздел | Что лежит |
|---|---|
| `…\Policies\Microsoft\Windows\WindowsUpdate` | Активные часы (`SetActiveHours`, `ActiveHoursStart/End`) и дедлайны (`SetComplianceDeadline`, `ConfigureDeadline*`) |
| `…\Policies\Microsoft\Windows\WindowsUpdate\AU` | Расписание установки (`NoAutoUpdate`, `AUOptions`, `ScheduledInstall*`) и перезагрузки (`NoAutoRebootWithLoggedOnUsers`, `AlwaysAutoRebootAtScheduledTime`) |

`SetComplianceDeadline = 1` обязателен: без него все `ConfigureDeadline*`
игнорируются. Политики `AU` не действуют на Windows 10/11 Home — нужна
редакция Pro или выше.

### Запрет тихой доустановки приложений из магазина

Windows умеет сама доставлять приложения в свежий профиль — Candy Crush,
промо-плитки и прочее. Закрывается это с двух сторон:

| Раздел | Что отключает |
|---|---|
| `…\Policies\Microsoft\Windows\CloudContent` | Политики на всю машину: `DisableWindowsConsumerFeatures`, `DisableCloudOptimizedContent`, `DisableConsumerAccountStateContent` |
| `HKCU\…\ContentDeliveryManager` | Доставка в конкретный профиль: `SilentInstalledAppsEnabled`, `PreInstalledAppsEnabled`, `OemPreInstalledAppsEnabled`, `PreInstalledAppsEverEnabled`, `ContentDeliveryAllowed`, `FeatureManagementEnabled`, `SubscribedContent-*` |

Главный здесь `DisableWindowsConsumerFeatures`: он машинный и действует на всех
пользователей. Ветка `HKCU` применяется только к той учётной записи, под
которой отработала постустановка, то есть к `Admin`. Если на машину потом
зайдёт доменный пользователь, его профиль прикроют машинные политики, но
пользовательские к нему не применятся — за это отвечает групповая политика или
правка профиля по умолчанию.

> Политики `CloudContent` не действуют на Windows 10/11 Home — нужна Pro или
> выше. На Home остаётся только ветка `HKCU`.

По Windows Update текущий набор: обновления ставятся по расписанию в 03:00 каждый день, активные
часы 09:00–23:00, принудительных перезагрузок при вошедшем пользователе нет,
дедлайны — 7 дней на крупные обновления, 5 на безопасность, 2 дня льготного
периода.

### Системные настройки

Секция `system`: часовой пояс, раскладка по умолчанию, удаление OneDrive, имя
компьютера, отключение гибернации и засыпания от сети, RDP, перезапуск
Проводника, перезагрузка в конце.

#### Удаление OneDrive

`"removeOneDrive": true` снимает клиент целиком:

1. завершает процесс `OneDrive.exe`;
2. запускает `OneDriveSetup.exe /uninstall` — проверяются все три расположения:
   `System32`, `SysWOW64` и профиль пользователя, клиент бывает установлен
   и машинно, и в профиль;
3. убирает пакет приложения, если в сборке Windows 11 OneDrive пришёл ещё и так;
4. вычищает записи автозапуска из `Run` в `HKCU` и `HKLM`.

Три правки реестра не дают ему вернуться и убирают значок: политика
`DisableFileSyncNGSC` и `System.IsPinnedToNameSpaceTree` для обеих веток
`CLSID` (64- и 32-битной).

> Папка `%UserProfile%\OneDrive` намеренно не удаляется: в ней могут лежать
> файлы пользователя, а снос клиента их не возвращает. Если папка не нужна,
> удаляйте её руками, посмотрев содержимое.

### Локали

| Параметр | Значение | Что задаёт |
|---|---|---|
| `InputLocale` | `en-US; ru-RU` | Раскладки клавиатуры; первая в списке — по умолчанию, то есть ввод стартует английским |
| `SystemLocale` | `ru-RU` | Язык для не-Unicode программ (кодовая страница 1251) — нужен 1С |
| `UILanguage` | `ru-RU` | Язык интерфейса системы |
| `UILanguageFallback` | `en-US` | Запасной язык интерфейса, если русского пакета нет в образе |
| `UserLocale` | `ru-RU` | Региональные форматы: дата ДД.ММ.ГГГГ, запятая как десятичный разделитель, рубль |

> `UILanguage ru-RU` работает только если русский языковой пакет есть в образе.
> Берите русский дистрибутив Windows; на англоязычном образе интерфейс
> останется английским (сработает `UILanguageFallback`), пока не доставите
> языковой пакет.

Раскладка по умолчанию английская закрепляется дважды: порядком в `InputLocale`
и параметром `system.defaultInputLanguage` в `postinstall.json` — при русских
`UILanguage`/`UserLocale` Windows иначе может переставить раскладку сама.

## Microsoft Office

Включается в опросе `oobe.ps1` («Ставить Microsoft Office?») или флагом
`office.enabled` в конфиге.

| `mode` | Что делает |
|---|---|
| `odt` | Берёт `setup.exe` из `Office\ODT\` на раздаче (или ставит ODT через winget) и выполняет `setup.exe /configure <configuration.xml>`. Для Office LTSC и томовых лицензий. |
| `winget` | `winget install Microsoft.Office` — Microsoft 365 Apps, лицензия активируется входом пользователя. |

**`configuration.xml` собирается из конфига, править XML руками не нужно.**
Оси те же, что в [farag2/Install-Office](https://github.com/farag2/Install-Office):
ветка, канал, компоненты.

```json
"office": {
  "enabled": false,
  "mode": "odt",
  "productId": "ProPlus2024Volume",
  "channel": "PerpetualVL2024",
  "edition": "64",
  "languages": ["ru-ru", "en-us"],
  "apps": ["Outlook", "Word", "Excel", "PowerPoint"],
  "pidKey": ""
}
```

| Поле | Значения |
|---|---|
| `productId` | `ProPlus2024Volume` — Office LTSC 2024, томовая лицензия; `O365ProPlusRetail` — Microsoft 365 Apps; `ProPlus2021Volume` — LTSC 2021 |
| `channel` | Для томовых LTSC — `PerpetualVL2024` или `PerpetualVL2021`; для подписки — `Current`, `MonthlyEnterprise`, `SemiAnnual` |
| `apps` | `Access`, `Bing`, `Excel`, `Groove`, `Lync`, `OneDrive`, `OneNote`, `Outlook`, `PowerPoint`, `Publisher`, `Teams`, `Word`. Пустой список — ставить всё |
| `pidKey` | Только для KMS/MAK; при AD-based активации оставьте пустым |

ODT принимает не список устанавливаемого, а список исключаемого, поэтому из
`apps` автоматически вычитается всё остальное. Набор по умолчанию — Outlook,
Word, Excel, PowerPoint — даёт восемь `ExcludeApp`. Опечатка в имени компонента
не проходит молча: установка прерывается с перечислением допустимых значений,
иначе `Wrod` просто означал бы «Word не ставим».

Если нужен свой готовый XML, укажите `configNasPath`, `configPath` или
`configUri` — он возьмётся как есть, а поля выше будут проигнорированы. Готовые
примеры лежат в [`office/`](office/), файл для набора по умолчанию —
[`configuration-ProPlus2024Volume.xml`](office/configuration-ProPlus2024Volume.xml).

Справочник параметров: [ODT](https://learn.microsoft.com/ru-ru/microsoft-365-apps/deploy/office-deployment-tool-configuration-options),
ключи KMS: [GVLK](https://learn.microsoft.com/ru-ru/deployoffice/vlactivation/gvlks).

> Project и Visio — отдельные продукты ODT (`ProjectPro2024Volume`,
> `VisioPro2024Volume`), а не компоненты. Через `apps` их не поставить, нужен
> свой `configuration.xml` со вторым блоком `<Product>`.

## Учётная запись и пароль

Файлы ответов создают локального администратора **`Admin`** с паролем **`Admin`**
и однократным автовходом. Пароль хранится в штатной обфускации unattend —
это base64, а не шифрование. Сменить:

```powershell
[Convert]::ToBase64String([Text.Encoding]::Unicode.GetBytes('НовыйПароль' + 'Password'))
```

и подставить результат в `<Value>` обоих блоков (`LocalAccount` и `AutoLogon`).
Чтобы потребовать смену пароля при первом входе, раскомментируйте второй
`SynchronousCommand` в `UnattendOOBE.xml`.

## Запуск sysprep вручную

`oobe.ps1` делает это сам, но иногда нужно руками. Запускать только от
администратора, путь — `C:\Windows\System32\Sysprep\sysprep.exe`.

**Повторно пройти OOBE на этой же машине** (то, что делает `oobe.ps1`):

```cmd
C:\Windows\System32\Sysprep\sysprep.exe /oobe /reboot /unattend:C:\ProgramData\oobe\UnattendOOBE.xml
```

Без файла ответов — OOBE со всеми вопросами:

```cmd
C:\Windows\System32\Sysprep\sysprep.exe /oobe /reboot
```

SID, драйверы и активация сохраняются: `/generalize` здесь намеренно нет.
Файл ответов должен содержать только проход `oobeSystem` — при `/oobe`
обрабатывается лишь он.

**Подготовить эталонный образ для развёртывания** (сбрасывает SID, удаляет
драйверы и сбрасывает активацию):

```cmd
C:\Windows\System32\Sysprep\sysprep.exe /generalize /oobe /shutdown /unattend:C:\ProgramData\oobe\UnattendOOBE.xml
```

Для виртуальной машины добавьте `/mode:vm` — тогда драйверы оборудования
сохраняются, но образ пригоден только для того же гипервизора:

```cmd
C:\Windows\System32\Sysprep\sysprep.exe /generalize /oobe /shutdown /mode:vm
```

> `/generalize` расходует счётчик rearm активации Windows (обычно их 3).
> Для обычного переразвёртывания рабочей станции он не нужен — хватает `/oobe`.

**Режим аудита** — донастроить систему под встроенным администратором до OOBE:

```cmd
C:\Windows\System32\Sysprep\sysprep.exe /audit /reboot
```

| Ключ | Что делает |
|---|---|
| `/oobe` | Следующая загрузка — этап OOBE |
| `/generalize` | Сброс SID, удаление драйверов и журналов; для захвата образа |
| `/audit` | Режим аудита вместо OOBE |
| `/reboot` / `/shutdown` / `/quit` | Перезагрузить, выключить или просто завершить работу |
| `/unattend:<файл>` | Применить файл ответов |
| `/mode:vm` | Образ для того же гипервизора, драйверы сохраняются |

## Диагностика

| Что | Где |
|---|---|
| Лог пост-установки | `C:\ProgramData\oobe\postinstall.log` |
| Лог ODT (Office) | `C:\ProgramData\oobe\*.log` |
| Применённый файл ответов | `C:\Windows\Panther\unattend.xml` |
| Ошибки применения файла ответов | `C:\Windows\Panther\setupact.log`, `setuperr.log` |
| Логи sysprep | `C:\Windows\System32\Sysprep\Panther\` |

`postinstall.ps1` не падает на одном сбойном пакете: в конце печатается список
невыполненных шагов, код возврата `1`. Повторный запуск безопасен.

## Правки .ps1 в этой папке

Скрипты содержат русский текст и запускаются Windows PowerShell 5.1, поэтому
сохраняйте их в **UTF-8 с BOM** — без BOM 5.1 читает файл как ANSI и
кириллица превращается в мусор. Файлы ответов, наоборот, — UTF-8 **без** BOM.
